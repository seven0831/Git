# 任务分解与依赖关系

> 任务严格按依赖关系排序：只有前置任务完成后才能开始后续任务。每个任务的"验收"是该任务完成的判定标准。

## 依赖图（概述）

```
T0 脚手架+初始数据 ──► T1 数据层 ──► T2 首页 ──► T3 列表页 ──► T4 详情页 ──► T5 发布页 ──► T6 测试与整体验收
```

## 任务清单

| # | 任务 | 依赖 | 验收标准 |
| --- | --- | --- | --- |
| T0 | 脚手架 + 初始数据 | — | `activities.json` 写入 26 条活动（与考核要求逐条一致）；`styles.css` 共享样式就绪 |

## 执行约定

- 每个任务完成后，先运行一次冒烟验证再进入下一个任务。
- 发现与 SPEC 冲突的地方，回到 SPEC 修订，再继续。
- 最终交付：4 页面纯前端应用 + 26 条初始数据 + 收藏功能 + 文档一致。
